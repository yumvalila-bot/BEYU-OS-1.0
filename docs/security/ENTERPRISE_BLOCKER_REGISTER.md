# Enterprise blocker register — PR #114

This register separates implemented controls from release acceptance. The baseline was `8fc176d353f04c64d2cef7d603df84b26affebfb`; `main` was fetched at `6e30cb0383dfff60c7826abde614a0dcf16e7eb1`. No production configuration, identities or infrastructure were changed. These are engineering owner roles, not assertions that a named person has accepted responsibility.

| Blocker / owner | Evidence and impact | Action and closure evidence |
|---|---|---|
| Foundation pre-stream boundary — application security and Foundation owners | Known Foundation pages have a refusal-only live preflight and retain independent page/API guards. Isolated HTML/RSC/prefetch denials, logged denial, logout/expiry, browser navigation and unreachable-DB 503 were exercised. Unknown Foundation paths now receive a generic no-store 404, and recursive page-catalogue parity is tested. A mock test of registry permission/scope revocation between preflight and rendering confirms that its independent guard does not read protected rows, but this is not a real HTTP race proof. A revocation or dependency change **between** preflight and independent rendering can still cause an already-streamed response to carry HTTP 200; other pages, actions, races and timeouts require further review. When session lookup itself fails, no actor is established and the DB audit store may also be down; only a sanitized technical log is possible. | Threat-model races, target changes and all navigation/action routes; prove no data leak and correct statuses under races, timeout and audit outages; verify deployment/runtime support. |
| Request-body boundaries — API and domain owners | `REQUEST_BODY_INVENTORY.md` is a heuristic, not an exhaustive inventory. It finds 123 direct JSON route files, many indirectly shared routes and other untraced body consumers. Fifteen Communications mutations now read bounded raw JSON once and preserve that raw payload for the idempotency hash; they use strict JSON media, UTF-8, syntax, shared 1 MiB and structural limits. Live HTTP tested malformed JSON and unsupported media on all 15; contacts also covered replay, size, UTF-8 and complexity. Compatibility with every domain payload is unverified. Multipart, uploads, aliases, webhooks and backend packages need individual review. | Trace each handler and input stream; approve domain-specific byte, structure, content-type and upload limits; prove malformed, oversized, adversarial and legitimate payloads, idempotency, and no unintended writes. |
| Health federation — enterprise identity and Health security owners | BEYU browser sessions are opaque and are not Health backend JWTs. Approved issuer/audience, keys, identity mapping, MFA assurance, token lifetimes, replay and revocation contracts are not established; no cross-system SSO is claimed. | Owner-approved trust contract, secure provisioning and end-to-end expiry/revocation/MFA tests. See `HEALTH_SESSION_FEDERATION_CONTRACT.md`. |
| Persisted governed workspace assignment — governance and workspace owners | A role-to-workspace catalog and assignment policy is not approved or implemented. Launcher destinations and canonical hostnames are not authority. | Approve canonical catalog, ownership, scope, delegation and two-stage authorization; migrate and test deny-by-default. See `WORKSPACE_ROUTING_REVIEW.md`. |
| RLS, SOD, CAP_POSTING and audit — security, DB and finance owners | Existing independent controls remain in place; cross-cutting full-domain review and negative-path evidence for every requested flow are incomplete. Audit may be unavailable during an authorization outage. | Map each authoritative enforcement point and actor scope; prove runtime RLS, SOD, posting lock, audited denial, failure and revocation with isolated tests. |
| Accessibility, responsive and persona coverage — UX/accessibility and domain owners | The homepage and shared sign-in passed the 17-size document-overflow/primary-element matrix. Automated checks cover selected entry and Foundation screens only; full workspace matrix, real zoom/touch/safe areas, manual keyboard/assistive technology and full persona workflows are incomplete. Automated axe does not certify WCAG. | Complete the specified matrix and manual WCAG 2.2 AA review, document failures and retest. See `ENTRY_ACCESSIBILITY_REVIEW.md`. |
| Full regression exceptions and final-head evidence — release engineering | The historical `8fc176d` full run passed 5,895 tests with 12 skips and 31 TODOs; those are not passes. The exception register lists each exact case, risk and execution prerequisite. The `763feec` GitHub root regression failed seven Foundation-denial assertions that still expected 200; the tests were updated to require 403 for Foundation (and preserve existing behavior elsewhere), then 60 targeted tests passed. Later changes need their own full final-head run and CI results. | Execute feasible isolated exceptions, implement TODO coverage, run full regression on final SHA, triage each failure/skip and record exact evidence. See `REGRESSION_EXCEPTIONS.md`. |
| Administrator bootstrap — identity and database security owners | A separately provisioned, migrated and seeded disposable database with the restricted runtime and governance roles produced 3 passes and **2 failures** in `tests/bootstrap/enrollment-http.test.ts`: weak-password validation and end-to-end enrollment returned HTTP 500. PostgreSQL reported permission denied on `admin_bootstrap_state` during `SELECT FOR UPDATE`; the reviewed runtime allowlist intentionally marks it read-only while the enrollment service uses the runtime DB transaction to lock and update it. A follow-up run with the HTTP server and test fixtures using the same separately provisioned database again produced 3 passes and 2 failures; the failures now return sanitized no-store 503 rather than leaking database errors into logs. `FOR UPDATE`, `UPDATE` and `DELETE` were independently refused for the non-bypass runtime role. This still blocks the ceremony. | Design and approve a narrowly scoped bootstrap authority boundary with terminal seal, concurrency, audit and least privilege; do not grant broad runtime mutation privileges. Re-run all 5 tests using restricted roles and prove unauthorized runtime updates remain denied. |
| Deployment readiness — infrastructure and security owners | Production DNS/TLS, host-only versus explicitly approved shared cookie, Health trust, deployment security and operational monitoring are not verified. | Obtain decisions and independently validate the actual production configuration; no deployment is authorized by this PR. |
