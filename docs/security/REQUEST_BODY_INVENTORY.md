# API request-body inventory

Generated by `node scripts/inventory-request-bodies.mjs`. This is a static lexical inventory of 378 root Next.js route files, not proof of safety. It identifies common direct request readers and selected shared helpers, but aliases, helper-internal reads, re-exports, middleware, server actions, backend packages, multipart libraries and other body consumers require manual tracing. Multiple labels can occur in one file; absence of a label does not mean a route is body-free.

Files with direct request/req/ctx.request JSON calls: 123; direct text calls: 0; formData: 0; parseBody: 63; bounded JSON directly: 15; credential boundary: 5; bounded text: 2. These counts are overlapping and do not certify contracts or schema-specific limits.

The web/mobile login, recovery request and two bootstrap credential endpoints require JSON and a 16 KiB streaming cap. Payment and communications webhook routes use their existing 256 KiB cap while reading raw text, preserving signature inputs; provider Content-Type rules are not generalized. Fifteen Communications idempotent mutations now read bounded JSON once, validate before claiming a key, and hash the original payload for replay. Shared parseBody is bounded and rejects preconsumed streams, but direct JSON readers, indirect calls, issue accumulation and other formats remain a release blocker. Domain owners must review limits and integrations before expanding any global cap.
